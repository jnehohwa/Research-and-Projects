Introduction
I built KasiSwap as a Customer-to-Customer e-commerce prototype for South African township and informal-
economy users. The main idea is simple: buyers and sellers should be able to trade goods online with more
trust than they would get from screenshots, off-platform chats, and manual EFT proof. The prototype supports
searchable listings, in-app messaging, protected order states, seller verification, reviews, disputes, and an
admin website.

The submitted implementation is the clean PHP/MySQL repository, not the separate TypeScript/React portfolio
prototype. It uses PHP, MySQL, HTML, CSS, and a small amount of JavaScript. I kept the interface responsive
and low-data conscious because the target users are likely to use phones, prepaid data, and slower
connections.

Important prototype note: the payment-hold flow is a sandbox simulation for academic demonstration. It
models escrow-like order states, but it is not a real regulated escrow or payment service.

Sample PHP Code : Secure Login and RBAC
Source file: app/security.php

Why this matters: This shows prepared statements, password verification, session regeneration, and audit
logging. Those are core controls for a role-based PHP application.
  function sign_in(string $email, string $password): bool
  {
      $stmt = db()->prepare('SELECT * FROM users WHERE email = ? AND status = "active" LIMIT 1');
      $stmt->execute([$email]);
      $user = $stmt->fetch();

      if (!$user || !password_verify($password, $user['password_hash'])) {
          return false;
      }

      session_regenerate_id(true);
      $_SESSION['user_id'] = (int) $user['id'];
      log_audit('login', 'user', (int) $user['id'], 'User signed in.');
      return true;
  }

10. Security, Trust, and Maintainability
The security work is not treated as an extra feature. It is part of the core design because a C2C marketplace
only works if users can trust the platform workflow.

●   Prepared statements reduce SQL injection risk across database reads and writes.
●   Passwords are checked with password_verify() and stored as hashes instead of plain text.
●   session_regenerate_id(true) is used after login to reduce session fixation risk.
●   CSRF tokens protect state-changing POST forms.
●   Output escaping with e() reduces XSS risk in listing and user-generated content.
●   RBAC protects admin routes and separates buyer, seller, and admin abilities.
●   Order-state rules prevent sellers from shipping before platform-confirmed sandbox payment.
●   Audit logs preserve traceability for login and admin actions.
●   config.local.php is kept out of Git so live credentials are not committed.

KasiSwap demonstrates a working PHP/MySQL C2C marketplace prototype that responds directly to the
